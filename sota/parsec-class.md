# Parsec-Class Interactive Desktop and Workstation Transports


> **Research date:** 2026-08-28  
> **Method:** capability-class comparison, not an assertion that every row is a drop-in competitor. Product status and exact feature matrices change; primary project/vendor links are recorded per row. Vendor performance claims are treated as claims until reproduced under the reference scenarios.  
> **Decision rule:** integration value is determined by measured stage cost, semantic fidelity, control/API quality, security boundary, and maintenance risk—not brand recognition.


## Scope and result

This class includes encoded full-desktop/game/workstation transports plus adjacent browser/session products that can carry the visible interactive surface. It contains **32 systems**, exceeding the requested minimum of 25. The practical leaders for this project are Looking Glass for same-host VFIO, Sunshine/Moonlight for open encoded LAN/WAN, Parsec for low-friction WAN, RDP/RAIL for Windows semantics, Xpra/Waypipe for Linux semantics, and OOB hardware when software is unavailable.

## Product conclusion

No product above owns all required layers. The packaged shell must choose among them automatically. A route that encodes on one physical host when KVMFR, DMA-BUF, shared GPU handles, virtio or shared memory are possible is a compiler failure. Conversely, insisting on a semantic or shared-memory path across an unsupported WAN is also a failure. The differentiator is the route compiler and common graph—not another one-size-fits-all streamer.
