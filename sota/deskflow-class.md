# Deskflow-Class Input Continuity, Software KVM, and OOB Control


> **Research date:** 2026-08-28  
> **Method:** capability-class comparison, not an assertion that every row is a drop-in competitor. Product status and exact feature matrices change; primary project/vendor links are recorded per row. Vendor performance claims are treated as claims until reproduced under the reference scenarios.  
> **Decision rule:** integration value is determined by measured stage cost, semantic fidelity, control/API quality, security boundary, and maintenance risk—not brand recognition.


## Scope and result

This class contains **40 systems** spanning software KVMs, ecosystem continuity features, mobile/pen endpoints, raw USB transport and KVM-over-IP. OOB hardware is included because a product that claims one seat across bench machines must remain usable before boot and after the OS or GPU path fails.

## Product conclusion

Deskflow is the best broad open baseline but is only an adapter. The product requires a central pressed-state ledger, exclusive fenced focus leases, raw-relative mode, output/audio transactions, agent non-stealing policy and OOB fallback. No software KVM alone provides those guarantees.
