# Distributed and Heterogeneous Compute Runtime Class


> **Research date:** 2026-08-28  
> **Method:** capability-class comparison, not an assertion that every row is a drop-in competitor. Product status and exact feature matrices change; primary project/vendor links are recorded per row. Vendor performance claims are treated as claims until reproduced under the reference scenarios.  
> **Decision rule:** integration value is determined by measured stage cost, semantic fidelity, control/API quality, security boundary, and maintenance risk—not brand recognition.


## Scope and result

This comparison covers **36 runtimes, schedulers, languages and communication substrates**. No single system combines arbitrary-binary interposition, hard real-time isolation, per-window presentation, object residency, same-host PCIe paths and WAN jobs. The design should borrow Legion/Realm region and mapping ideas, StarPU/PaRSEC heterogeneous DAG scheduling, Ray-style object references, Charm++ overdecomposition, and UCX/libfabric/NIXL transport abstractions—without inheriting one ecosystem wholesale.

## Differentiation

The product’s novelty is not merely distributing jobs. It compiles execution, object residency, presentation and human/agent I/O together, while making the smallest interceptable operation a capability floor and adaptively fusing operations into regions when movement/coordination cost dominates.
