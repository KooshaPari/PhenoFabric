# Feasibility Boundaries and Honest Claims

## Feasible product core

- one shell and graph over specialized adapters;
- central seat/focus transactions and workspaces;
- same-host Looking Glass/virtio/shared-memory paths;
- LAN/WAN encoded full desktops and selected semantic apps;
- platform audio/input/display endpoints;
- protected real-time resource policy;
- agent realm/surface publication;
- explicit TaskSpec and object-aware distributed placement;
- adaptive fusion/fission for cooperative or interceptable regions.

## Feasible only under bounded conditions

- networked live DSP: only where graph slack and clock/network evidence permit;
- GPU P2P/shared handles: only on supported topology/driver/security domains;
- VM/process migration: compatible state, devices and destination;
- per-window pixel proxy: application/window/protected-surface matrix;
- syscall/function routing: selected workloads and locality tiers with positive break-even;
- CXL/RDMA/GPUDirect: hardware and operational support.

## Not a truthful general claim

- all remote RAM/VRAM becomes uniform local memory;
- arbitrary Windows process live-migrates to macOS;
- every syscall is profitably routed across the WAN;
- secure desktop/DRM can always be captured;
- a remote game/render/audio critical path always beats local execution;
- one codec/profile is optimal for desktop, gaming, HDR and color work;
- an agent may safely seize human focus because it created a realm;
- software recovery replaces independent OOB access.

The runtime may make location transparent at the UX/API level while remaining aggressively location-aware internally.
