# Research Hypotheses and Falsification Register

| ID | Area | Hypothesis | Falsification / rejection condition | State |
|---|---|---|---|---|
| RH-001 | Locality-first routing | For a same-host VFIO surface, KVMFR/Looking Glass produces lower total latency and lower CPU/GPU overhead than any encode/decode route at equivalent visible quality. | Reject if an encoded route reproducibly beats it without hidden queue/quality loss. | Proposed |
| RH-002 | Stage elimination | Removing one full memory-domain copy produces a measurable p95/worst improvement under contention even when idle median changes little. | Reject if copy removal adds synchronization cost that erases total benefit. | Proposed |
| RH-003 | Central input broker | A persistent evdev→uinput broker switches among N realms faster and more safely than direct QEMU device grabs. | Reject if broker overhead or failure rate exceeds direct-grab baseline. | Proposed |
| RH-004 | Pressed-state transaction | Synthesizing releases before focus commit eliminates stuck modifiers/buttons without materially increasing switch latency. | Reject if failures persist in randomized million-switch corpus. | Proposed |
| RH-005 | Independent media queues | Separating input, audio, video, clipboard and bulk queues reduces tail latency during large transfers. | Reject if shared scheduling performs equivalently under impairment and saturation. | Proposed |
| RH-006 | Content-aware video policy | Desktop 4:4:4 and game frame-priority policies outperform one fixed codec profile on user-visible quality per resource cost. | Reject if blind/metric tests show no material benefit. | Proposed |
| RH-007 | M1 Pro sink viability | The 2021 M1 Pro can sustain the selected 10-bit high-refresh stream mode with acceptable decode/compositor cost while running ordinary local work. | Reject or lower mode if decode/thermal/frame pacing misses gate. | Proposed |
| RH-008 | HDR intent preservation | Explicit source/sink color metadata and controlled transforms reduce clipping/gamut errors versus OS-default black-box paths. | Reject if instrumentation and visual targets show no improvement. | Proposed |
| RH-009 | Audio RT reservation | Cross-resource admission and relocation of background work prevent Ableton xruns more effectively than process priority alone. | Reject if background relocation does not improve worst-case audio stability. | Proposed |
| RH-010 | Remote DSP break-even | Selected coarse DSP/plugin nodes can run on another LAN host when two-way audio/control latency plus jitter remains below graph slack. | Reject per node when deadline margin is not robust. | Proposed |
| RH-011 | Explicit TaskSpec baseline | Cooperative task placement captures most practical distributed benefit before transparent syscall interposition. | Reject if high-value workloads cannot be expressed without transparent interception. | Proposed |
| RH-012 | Data-aware placement | A slower compute node with local inputs often beats a faster remote accelerator once transfer and queue cost are included. | Reject if test corpus never changes winner after data cost. | Proposed |
| RH-013 | Adaptive region fusion | Fusing repeated same-destination atomic decisions reduces overhead while preserving placement quality. | Reject if fusion increases completion time or misses changing constraints. | Proposed |
| RH-014 | Region fission | Fission triggered by contention/locality change improves performance over static pinning without thrash under hysteresis. | Reject if fission oscillation or overhead exceeds benefit. | Proposed |
| RH-015 | Predictive prefetch | Workload-sequence prediction for builds, game E2E and agent tools reduces cold-start transfer/queue latency. | Reject if cache pollution/waste dominates p95 gain. | Proposed |
| RH-016 | Speculation | Bounded speculative execution improves tail completion for high-variance agents/tasks within an explicit waste budget. | Reject if cancellation/resource externality violates foreground SLOs. | Proposed |
| RH-017 | Surface/execution independence | Moving only presentation/seat is the optimal desk↔couch operation in most cases. | Reject if execution migration improves experience often enough to justify default complexity. | Proposed |
| RH-018 | Semantic before pixel | RAIL/Xpra/Waypipe paths produce better window/IME/clipboard behavior and lower resource cost than pixel proxies for supported apps. | Reject per application when protocol semantics are incomplete or slower. | Proposed |
| RH-019 | Surface atlas | Packing multiple mostly-static proxy windows into shared streams reduces encoder/session pressure without unacceptable interaction latency. | Reject if damage/atlas management costs exceed dedicated streams. | Proposed |
| RH-020 | Lease fencing | Monotonic fencing tokens prevent split-brain input/output ownership during coordinator/network partitions. | Reject only on correctness failure; performance is secondary. | Proposed |
| RH-021 | Agent non-stealing | Attention requests and surface catalog preserve user flow while remaining fast enough for agent inspection. | Reject if users consistently prefer automatic focus under defined policies; retain explicit opt-in. | Proposed |
| RH-022 | OOB value | Hardware KVM paths materially reduce mean recovery time for bench/failed systems despite inferior daily media quality. | Reject only if software path remains available in all tested failure classes. | Proposed |
| RH-023 | Explainability | Counterfactual route explanations accelerate debugging and improve trust without overwhelming ordinary users. | Reject or simplify UI if users cannot act on explanations. | Proposed |
| RH-024 | Cross-product events | Stable IDs/events integrate AgilePlus/thegent/Tracera/ledgers without shared storage and with acceptable reconciliation cost. | Reject if event reconciliation becomes less correct than explicit API queries. | Proposed |
| RH-025 | Atomic FUSE relocation | For selected I/O-heavy agent/build patterns, filesystem-level interception can coalesce or move execution with positive net benefit. | Reject as a product path if overhead/security exceed measured gain. | Proposed |
| RH-026 | Syscall mediation | Syscall-level routing has a narrow profitable domain on same-host/shared-memory or very fast fabric, not a universal domain. | Reject universal claim if any distribution tax is ignored; graduate only bounded cases. | Proposed |
| RH-027 | Kernel routing | Accelerator-kernel placement can be changed at graph/capture boundaries more profitably than at arbitrary API calls. | Reject if data residency makes alternate device consistently worse. | Proposed |
| RH-028 | Mixed-load telemetry | Idle benchmarks substantially overpredict user experience; mixed-load p99/worst correlates better with satisfaction. | Reject if idle and mixed-load rankings remain identical across corpus. | Proposed |
| RH-029 | Adaptive degradation | Predictable quality ladders maintain interaction better than queue buildup under resource loss. | Reject if users prefer occasional stalls over controlled quality reduction for a workload class. | Proposed |
| RH-030 | One shell value | A unified workspace/graph shell reduces action count and error rate compared with operating separate KVM, streamer, audio and VM tools. | Reject if integration complexity creates more failures than it removes. | Proposed |

A negative result is preserved as evidence and may produce an ADR rejecting or narrowing the feature. Research is not complete when a favorable benchmark appears; it is complete when the result survives mixed load, faults and counterfactual alternatives.
