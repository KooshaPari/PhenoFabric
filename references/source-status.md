# Source and Claim Status

## Labels

- **Primary:** official specification, kernel/project documentation, source repository or paper.
- **Vendor-primary:** official product documentation; reliable for availability/configuration, not comparative performance.
- **User-owned:** user repository, prompt or prior whitepaper; authoritative for intended ecosystem/product boundaries.
- **Secondary:** reputable analysis/community material used to identify edge cases, never alone for a hard claim.
- **Experimental:** young project or feature requiring direct audit and benchmark.
- **Archived:** useful prior art, not a new dependency.
- **Unresolved:** excluded from implementation decisions until identity/source is confirmed.

## Freshness

This corpus is dated 2026-08-28. Product status, licensing, supported OS versions, APIs and prices are mutable and must be rechecked before procurement, integration or public comparison. Stable standards and architecture concepts still require version pinning.

## Performance claims

Numbers published by products are recorded only as vendor claims unless their exact methodology and boundary are reproduced. For example, capture-to-client-enqueue is not labeled glass-to-glass latency.
